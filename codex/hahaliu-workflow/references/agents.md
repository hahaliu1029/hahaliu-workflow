# 子智能体分工

## 何时拆分

只在下列情况派子智能体：

- 多个只读问题域可以独立调查。
- 实现切片拥有不重叠的文件所有权和验收标准。
- Standards、Spec、安全等评审需要上下文隔离。
- skill 创建或重大修订需要 fresh-context 前向测试。

小任务、共享契约尚未冻结、多个切片会改同一文件、任务存在严格串行依赖时留在主上下文。单文件、小 delta、单一 Standards/correctness 轴的评审也留在主上下文；只有多轴并行、高风险镜头或大 delta 确需上下文隔离时才派子智能体。协调、权限判断、目标契约和最终综合不得外包。

## 派发规则

1. 默认继承主模型；只有任务明确要求且当前平台支持时才指定模型或 reasoning effort。
2. 独立评测用 fresh context，只传 skill 路径、原始 artifact、用户式请求和必要边界；不传预期答案、疑似 bug 或拟议修复。
3. 并行实现前按文件所有权切分。共享 schema、接口和迁移顺序由主上下文先冻结。
4. 子智能体不得执行未经用户本次明确授权的 Git 写、发布、外发或生产副作用。
5. 子智能体返回 BLOCKED/NEEDS_CONTEXT 时补足上下文或调整任务；不要用相同 prompt 反复硬闯。
6. 主上下文用 live 文件、命令和测试验真，不把子智能体“完成”自报当证据。

## Prompt 检查单

- 明确目标、范围、非目标和验收标准。
- 给出工作目录、涉及文件、允许修改的文件所有权和验证命令。
- 写清楚只读或可写边界，以及禁止 Git 写/发布/外发。
- 约定交付：结果、文件、命令输出、风险；无法完成时返回 BLOCKED/NEEDS_CONTEXT。
- 对评审任务只提供任务 delta 或原始 artifact，不泄漏主上下文结论。

## 常见分工

| 场景 | 子智能体职责 | 主上下文职责 |
|---|---|---|
| 多目录侦察 | 每个 agent 负责一个问题域，只读返回证据 | 对齐调用链并选主链 |
| 独立 tickets | 每个 agent 只改自己的文件集合并跑定向验证 | 冻结共享契约、处理集成 |
| 双轴评审 | Standards 与 Spec agent 分开看同一 patch | 验真、去重、保留真实分歧 |
| 安全评审 | 只看认证、权限、输入、路径、数据出域 | 结合产品语义定严重度 |
| skill 前向测试 | 像真实用户任务一样使用 skill | 检查行为与 artifact，修订后重测 |

不要让子智能体读取或概括当前选中 skill 的创建规范来替代主智能体；主智能体必须亲自读取并遵守这些指令。
